## 2. 前置第一件事：黑胶带受控标定（照 8-28 钉极性的方法）

TCRT 模块是**阈值比较器而非模拟量**（翻转点约 5cm），必须实测黑胶带能否翻 white：

1. 逐工况测读（串口打印 `left/right white/black`）：
   - 白桌面/白纸（反射强）→ 预期 **black**（低电平）；
   - **黑色电胶带压线 → 预期 white？这是关键项**：深色吸光反射弱，8-28 已见深色台面误报 white，黑胶带大概率同；
   - 悬空/超出 5cm → **white**（= 防坠落危险信号，与黑线同码，见 §8 冲突提示）；
2. 量几何：两探头间距 d、胶带宽 w（15~20mm 时 w 与 d 的相对大小决定"双 white"出现频率）；传感器离地高度；
3. 复核物理左右映射（F.0 结论：右轮近沿 → EDGE_RIGHT，开工再手机确认一次）；
4. 输出：真实真值表记入本节 + 决定决策宏取值。**结论先于一切代码。**

- 地面白度不均/阴影 → 双读数抖动：去抖 2 拍 + 放慢速度；
- 双 white 判定：若实测 w > d（两探头同时压线），则"双 white=直行"是常态而非异常，决策宏须按几何实测定（§2 已列为必测项）。

## 9. 场地规则（9-02 老师实锤，USER当面问得）

> ⚠️ **路口形态以 §10 为准**：本节"T 型一入两出"经二次确认为树状发散（主路+单侧岔路、角度未知）；横线/胶带/无环规则不变。

| 项 | 规则 |
|---|---|
| 分叉路口 | **T 型（一入两出）**，无十字 |
| 终点标识 | **两条黑色横线**（垂直于道路），两线间距不长（具体数值未给，实测反推） |
| 错误路线尽头 | **一条黑色横线**（垂直于道路） |
| 胶带宽度 | **约 2cm，窄于左右红外探头间距**（探头间距标定时实测，§2） |
| 场地环 | **无环**（树状迷宫，左手法则够用） |

### 推导出的传感器语义（极性：压线=white / 白地=black）

- 直行循线段：线宽 2cm < 探头间距 ⇒ 几何上不可能双探头同时压线 ⇒ **双 white 只会出现在横向特征处**（路口横段/尽头横线/终点横线），是零歧义可靠信号，直行抖动不会误触发。
- 循线常态三态：单白转向 / 双黑（双白地）= 居中直行或丢线。
- **双 white 事件 = 统一入口**：停车 → 走判定流程（见下）。

### 双 white 后的判定流程（框架，实施时定稿）

1. 停车（去抖 N 拍确认，防阳光直射误报——8-29 教训）；
2. **探支线**（T 路口与尽头横线在此处同码，传感器分不出，只能靠动作分）：原地左转 ~90°（编码器闭环，24 脉冲/度现成）→ 能重新捕获线 = 左支线存在 → 走（左手法则优先左）；左无 → 右扫 ~180° 探右支线；有 → 走；
3. 左右皆无支线 ⇒ 当前是**横线**（非路口）：回原航向缓行，用遥测里程计开窗——**D_max 内再遇双 white = 终点第二条横线 → 停车（完赛）**；窗口内只见双黑（白地）= **错误路线尽头 → 掉头 180° 原路返回**；
4. 横线本身有横向长度，"探支线"不能只看转向瞬间有没有线（横线边缘会骗），要看转向后**沿线能持续走**（前进 D_probe 内丢线=伪支线，撤回再探另一侧）。D_probe / D_max 初值实测收束。

### 待实测/待确认参数

- D_max（终点双线间距窗）：老师只说"不是很长"，落地用遥测里程计实测反推（初估 10~30cm 窗）；
- 横线横向长度 vs 探头间距：影响探支线时的假阳性窗口；
- 非路口的 90° 直角弯（迷宫线自身拐弯，非分叉）：走增量②丢线找回流程，不在双白入口处理；
- 阳光直射会误报 white（8-29 实锤）→ 双白判定必须去抖 N 拍 + 考核时避开直射/侧面遮光。

### T 路口 vs 尽头横线"同码"的根本论证（9-02 补充）

- 两者唯一的物理差异 = **横向胶带的延伸长度**（T 手臂是路、线持续；尽头横线是标记、短即断）。双探头朝地、无侧视传感，**静态不可区分，只能靠运动探测把长度差翻译成读数差**。
- 推论：探测动作 = 左手法则执行本身——双白停车 → 左 pivot 90° → 前进开窗看线持续性，探中即左支（循线走），探不中退回探右，左右皆空才是横线（再分终点双线/尽头单线）。不需要独立"分类阶段"。
- 防假支线：判据不是"转完有没有线"（横线边缘会骗），而是"线能否持续超过**横线半长+余量**"；横线横向长度落地实测后定 D_probe。

### 角度扫描：支线探测从"步进盲转"升级为"边转边看"（9-02 USER问 Y 型岔口触发）

- 问题：固定 pivot 90° 后再找线，**Y 型/斜角支线会被转过头**（支线 45° 斜出时转到 90° 已越过 45°，前进越走越远），且依赖"支线必须垂直"的假设。
- 解法：编码器闭环慢转 = **角度扫描**（24 脉冲/度给朝向基准），旋转全程盯红外——探头扫过支线胶带的瞬间即暴露支线方向；扫到接触即停转，再用**前进 D_probe 验证线持续性**（最终裁判不变，防横线边缘假象）。
- 收益外溢：同一机制还覆盖 **90° 直角急弯**（角块 2×2cm 盖不满双探头、不触发双白，循线环会丢线）与通用丢线找回——岔口探测/急弯找回/丢线恢复三合一，即增量②④的具体形态。
- 官方场地为 T 型，Y 属规格外鲁棒性，成本≈0（扫描期多读传感器）。

### "线持续"判据的实现（9-02 USER追问细化）

- 循线环是**骑线结构**（线 2cm < 探头间距）：居中=双黑（线藏两探头之间），单白=漂移纠偏信号——"一侧探头始终压线"几何上不可能，判据不能用"有无压线"。
- **判据 = D_probe 窗口内的纠偏事件频率**：真支线→摆动使线周期性压到单侧探头（循线环持续产生转向纠正）；假支线（横线边缘假象）→开过横线端头后零接触、双黑长连续。
- **不对称中止**：连续双黑 > T_max 拍（初估 30 拍≈300ms≈1~2cm 零接触）→ 立即判假象、里程计盲退撤回，假支线 1~2cm 内识别；确认真支线才走满 D_probe。（沿用 F.0 危险快判/安全慢确认思路。）
- **防"循线太稳"误判**：探测前进段加主动小摆动（dither，左右交替微偏置 ~500ms 换向），逼着存在的线周期性过探头——检测确定性化，不靠跟踪噪声碰运气。T_max/D_probe/摆幅落地标定。

### USER提议的"180° 自旋扫线"方案评估（9-02，部分采纳）

- 提议：支线判定时前进一段 → 车身 180° 旋转 → 压到线=支线（再转回正向循线）/ 没压到=走错（直接开回）。
- **采纳的内核**：主动旋转逼线过探头，破解"居中骑线=双黑 与 丢线=双黑"的静态歧义——与 dither/角度扫描同宗；"没线则顺势开回"的返程设计等价于尽头掉头，保留。
- **否决的两点**：① "压到线=支线"会被尽头横线骗（横线横向延伸同样会被压到）——判据必须是线的**持续性**而非单次接触；② 裸转 180° 丢失接触方向信息（左支/右支/身后来路不可分，左手法则无法执行），且判定后再转 180° 回正=双倍原地转引入侧滑与里程误差。
- **合并结论**：旋转保留，但带编码器角度记录（扫到接触即知支线方向）、扫到即停（已对准方向，省回程旋转）、前进窗口验证持续性（防横线假象）——即 §9 角度扫描方案。

### 角度扫描的团块过滤与 Y 型固有弱点（9-02 补充）

- **团块过滤**：双白停车后扫描起步时，探头本来就压在横线/岔口团块上——起步几拍的接触不算支线；等转出团块（连续几拍无接触）之后再出现的接触才算。横线 2cm 厚，扫过 ~15-20° 探头弧即离带。
- **Y 型固有弱点（不防，记录在案）**：浅角 Y 岔口可能在双白触发前就被循线环的单白纠偏"拐进"某一支，选边由漂移决定、不守左手法则。正式场地为 T 型（老师 9-02 实锤），Y 只保"不丢线、找得回"，不保选边确定性。
- 三场景流程同构：双白停车 → 左扫（扫到即停）→ 前进验证（摆动+纠偏计数）→ 右扫 → 皆空走横线判定（D_max 内第二条=终点 / 超时=尽头掉头）。

## 10. 路口形态更正（9-02 二次确认）：非对称 T，树状发散

- **老师实锤**：只有一条主路，**每个结点恰好一条岔路**，角度/夹角未知；场地无环（树状）。岔路可在左或右。
- **传感器签名重推**：
  - 单侧岔路的胶带只铺到一侧探头下，主路 2cm < 探头间距 ⇒ **路口不再产生双白**；双白回归横线专用信号（尽头单横线/终点双横线），同码问题消失。
  - 路口新签名 = **单侧持续白**（岔路胶带从一侧探头下扫过，持续拍数长于正常纠偏）/ 浅角岔路时**左右交替白**（岔路与主路先后压探头）。签名随夹角变化，**落地实测采集**（标定清单新增项）。
  - **岔路捕获**：循线环会把单侧持续白当漂移纠正、自动拐进岔路——可作为左手法则的自然执行，也可主动抵抗，取决于策略选型。
  - 夹角未知 ⇒ 固定角度盲转彻底不可用，角度扫描（边转边看）成为唯一选项。
- **策略选型（开工前尽量问清老师）**：
  - 关键问题：① 主路是否必然到终点（岔路是否全为死路）？② 结点处主路几何上可否辨认（更直/更连续）？
  - **打法 A**（①是且②可辨）：永不进岔路，纯循线 + 抵抗岔路捕获 + 双横线停车，极简，无需路口状态机。
  - **打法 B**（否则）：路口检测停车 → 角度扫描定岔路方向 → 二选一探索（二叉结点）→ 死路掉头 + 记账（增量④状态机）。B 兼容 A 场地，**默认按 B 设计，老师确认 A 再裁剪**。
- 前进验证/dither/盲退/双横线终点判定等机制不受此更正影响。

## 11. 规则闭环与打法定稿（9-02 三次确认：主路必达终点，岔路/主路几何不可辨）

> 注（9-03）：本节三态框架已被 §13 六态状态机取代（NODE 拆为 NODE_SUSPECT / NODE_DECISION / PROBE，BAR_CHECK 不变；记账、扫描、验证机制全部沿用）。

- **老师最终实锤**：主路一定通到终点；岔路与主路在结点处**无法简单辨认**；场地标志只有单/双横线两种。
- **打法选型锁定 B（探索型）**：A（永不进岔路）依赖几何可辨，已死。
- **迷宫实为"梳子"结构**：主路=梳背（必达终点），岔路=梳齿（全部单横线死路、无子结点）。推论：
  - 结点记忆只需 **O(1)**：当前结点来路朝向 + 1bit"返程中"标志；无堆栈无地图。最坏行程有界 = 主路 + 每岔路一个来回。
  - 左手法则不再是正确性必需品（梳子结构任选其一+死路返回即可系统覆盖），仅作首次到达时的偏好启发。
- **状态机定稿**：FOLLOW（循线）—双白→BAR_CHECK（停车开窗 D_max：再现双白=终点完赛 / 超时=岔路尽头→掉头180°+置返程标志）；—单侧持续白（N拍阈值实测）→NODE（停车→**记录来路朝向**→角度扫描出全部去向→返程中则排除"岔路来向+记录来路"走剩余方向并清标志，首次到达则按偏好任选并记录来路）。
- **命脉机制：首次到达结点必须记录来路朝向**（编码器，短往返内角度误差可忽略）——岔路退回结点时两个去向几何不可辨，全靠这条记录排除"开回起点"。
- **连带要求：抵抗岔路捕获**——结点签名触发后压住循线环的单白纠偏冲动，先停车走显式决策；被循线环自动拐进岔路=没记录来路=记账全垮。这是循线环与结点状态机之间唯一的仲裁点。
- 角度扫描、前进验证（dither+纠偏计数）、盲退、双白去抖防阳光等机制沿用 §9/§10，不变。

## 12. 循线纠偏 vs 进岔路的区分仲裁（9-02 定）

- **骑线式纠偏**（循线环常态）：双黑=居中直行；单白=漂移 → 对侧减速差速微调，2 拍去抖切换，低速档（30~60）。
- 单个读数层面纠偏与岔路**同码**（都是单白），区分靠时间窗模式：
  - 普通漂移：单白**几拍内消失**（纠偏成功回中）；
  - **岔路：单白持续 + 左右交替白**（循线环向岔路纠正时主路从对侧探头下经过——短窗内两侧先后压线=两条物理线的铁证）；
  - 主路拐弯：单白持续但无交替（只有一条线，不会到对侧）。
- **两级检测**：
  - 交替白 = 确定性结点 → **停车**，角度扫描 + 显式决策（§11 NODE 状态）；
  - 单侧持续白超 N 拍（无交替）= 疑似结点 → 不停车，但**记录朝向+里程到账本**（循线照常，容忍被浅角岔路捕获——死路掉头回来时账可查）。
- 设计原则：**漂移会自己消失，岔路留下对侧证据；证据确凿停车决策，证据不足记账放行；梳子结构保证判错代价有界（一个来回），记账保证不死循环——宁可多记疑似结点，不可错放。**
- 待标定新增：交替白窗口拍数、持续白阈值 N（与弯道纠偏时长区分开，落地采集弯道/结点签名后定）。

## 13. 官方赛道实拍路线与六态状态机定稿（9-03）

> 9-03 USER在官方赛道实测：**主线循线全过 ✅（v4 FOLLOW 环验收合格）**，剩余工作 = 岔路判断。本节按实拍路线把 §11 三态框架细化为六态状态机，机制全部沿用 §9-12（角度扫描/前进验证/记账/双白开窗不变），只定稿状态划分与记账时机。

### 13.1 实拍路线图（USER手绘，9-03）

按行进方向：**左上端收束（起点侧，无标记）→ 缓弯向右 → 中上岔口①（岔路向右下浅角斜出）→ 右侧大回环（超过半圈的 U 形弯，全程单侧持续白的最长弯道样本）→ 折返左行 → 中下岔口②（岔路向下浅角斜出）→ 左下终点（双横线）**。

- 两条岔路均为**浅角 Y 型**（非垂直 T），按场地规则皆为单横线死路；主路必达终点、无环（梳子结构，与 §11 规则一致）。
- 冲击：**§9 记为规格外的"Y 型固有弱点"变成主线必答题**——浅角岔口大概率不产生停车级签名（交替白可能根本不出现），循线环会在判出结点之前就被单白纠偏自动拐进岔路。因此状态机定稿的核心：**疑似结点态不停车、先记账，容忍捕获**；死路掉头回结点时凭账本 + 返程标志排除来向，不错选"开回起点"。

### 13.2 六态状态机定稿

| 状态 | 进入条件 | 动作 | 退出 |
|---|---|---|---|
| FOLLOW | 默认（v4 循线环原样） | 双黑直行 / 单白粘性纠偏 / 急弯 PIVOT | 单侧持续白 > N 拍 → NODE_SUSPECT；双白（去抖）→ BAR_CHECK |
| NODE_SUSPECT（疑似结点） | 单侧持续白超 N 拍 | **不停车、循线照常**；记账（朝向+里程）；开 W 拍窗口盯对侧探头 | 对侧来白（交替 = 两条线铁证）→ NODE_DECISION；单白消失（=弯道）→ FOLLOW，**账本保留**（可能已被浅角岔路捕获） |
| NODE_DECISION（确定结点） | 交替白确认 | 停车 → 记来路朝向 → 闭环 pivot 角度扫描（边转边看、扫到接触即停、团块过滤）列全部去向 → 选向：**返程中排除「岔路来向 + 记录来路」走剩余方向并清标志；首次按偏好任选** | 扫到接触即停 → PROBE |
| PROBE（前进验证） | 扫描扫到接触 | dither 主动摆动 + D_probe 窗内纠偏事件计数 | 纠偏达标 = 真支线 → FOLLOW；双黑连续 > T_max = 假支线 → 里程计盲退撤回 → 回 NODE_DECISION 重扫 |
| BAR_CHECK（横线判定） | 双白去抖确认 | 停车缓行开窗 D_max | 窗内再现双白 → GOAL；超时只见双黑 → 尽头：掉头 180° + 置返程标志 → FOLLOW |
| GOAL | 开窗内第二条双白 | 停车完赛 | — |

- 账本 O(1)：来路朝向 + 1bit 返程标志 + 疑似结点记录（朝向+里程）。

### 13.3 实拍路线全程推演

### 18.3 新态 TRACE_WIGGLE（核心新增）

触发：watcher armed + 3cm 纯双黑静默。语义：主动摆动逼线过探头，判定"线还在不在车底"。

- 运动：左右交替差速 `WIGGLE_INNER/OUTER 50/70`（纠偏档同款），每 `WIGGLE_SWAP_TICKS 30`（300ms）换向一次；总行程预算 `WIGGLE_TRAVEL_S2 = 4cm`（4×S2_PER_CM）。横向摆幅设计目标 ~1.5~2cm（= (探头间距5cm − 线宽2cm)/2 + 余量），初值待落地标定。
- **摆中任何去抖后白色接触（单白或双白）→ 线还在**：写锚点 `blob_s2 = watch_arm_s2`（+θ/tick）、`blob_valid=1` → 撤防 → SETTLE → FOLLOW。打印 `WIGGLE: contact => line alive, anchor s=%ld`。
- **行程预算耗尽仍零接触 → 线真没了 = 死路**：打印 `WIGGLE: no contact => dead end`，`trace_enter_reverse(..., "dead end (wiggle)")`。**不写锚点**（这条双白是尽头线不是岔口——§17 锚点被 526 污染的修复）。
- wiggle 期间 watcher 挂起、FOLLOW 环不跑（独立态，无 PIVOT 升档）；传感器 stale 全局 STOP 路径照旧覆盖。
- 多次 wiggle 的自然幂等：线还在 → 撤防后若再有双白重新武装，无状态残留。

## 26. v7.1 参数重调（9-04 ④，USER定：速度×2 / 转向×4 / 链路 30ms）

### 26.1 USER的指令与病根诊断

"小车的速度变为原来的 2 倍，转向强度变为原来的 4 倍，Hi3861 与 STM32 交互调整运动状态的间隔改为 30ms 不要 100ms。现在由于转向力度过小导致直行的 PID 一直加力，最终导致一窜一窜的震荡。"

病根翻译：缓纠偏 50/70 差速太弱压不住 80 的直行速度；PIVOT ±14 坐在**粘滑带**里（v6.8 已实锤 14 粘滑：轮卡住 → PID 憋劲 → 挣脱 = 一窜一窜）。

### 26.2 映射表（怎么换算的，向USER明示）

| 项 | 原值 | 新值 | 依据 |
|---|---|---|---|
| DRIVE | 80 | 160 | 速度 ×2 |
| SETTLE | 50 | 100 | 速度 ×2 |
| REV | 50 | 100 | 速度 ×2 |
| CORRECT | 50/70 | 80/160 | 差速 20→80 = 转向 ×4，外轮=全速 |
| PIVOT | ±14 | ±56 | 整 ×4，且跳出粘滑带（震荡源头之一） |
| CAPTURE | 30/80×400ms | 40/160×200ms | 差速 120≈30°/100ms；最短弧时减半补偿，承诺转角 ~60° 不变；内轮 40 避粘滑 |
| COMMAND_RESEND | 100ms | 30ms | Hi3861→STM32 心跳/重发拍（有变化的命令本来就在 10ms 控制拍立即发） |
| STATUS_POLL | 100ms | 30ms | GET_STATUS 轮询——s2/θ 里程计刷新，×2 速度后 100ms 太粗 |

**刻意不动**：WIGGLE/REJOIN/REV_DOSE 的 40——角度预算制探测动作，标定在粘滑带之上；×4 扫掠会把胶带边沿停留时间压到 20ms 去抖窗之下，REJOIN 语法直接瞎。它们不在"直行震荡"的病根上。要调USER开口再调。

**也不动**：STATUS_LOG 打印拍 100ms（9600 波特 BLE 镜像吃不消 30ms，日志已串行）；所有 TICKS 时间常量（控制拍仍是 10ms，距离窗全走 s2 与速度无关）；传感采样本来就是 10ms + 20ms 去抖——事件反应链本来就不是 100ms，USER看到的 100ms 是打印拍。
