## 1. 背景与问题

阶段F 防坠落（Hi3861 决策 + STM32 执行，任务24 协议链路）当前状态：

- 传感器/去抖/状态机/FAULT_STOP/真双核链路全部实测通过；
- 转向角速度已标定：箱面 140 档原地旋转 ≈ **60°/s**（双向对称），180° = 300 ticks（3.0s），已写入宏；
- **8-29 桌面复测暴露的最后一个问题**：触发避让时"后退不够"，180° 原地旋转过程中车尾/轮探出桌沿掉下去。

根因（代码事实）：EDGE 状态的后退是**传感器提前终止**的——`Tabletop_Cliff_Avoidance.c:686-689`：后退满 `reverse_min`（500ms）且两传感器看到地面就停，或满 `reverse_max`（1s）强切。浅夹角接近时，传感器（轮前 2cm）一回到台面上方就满足退出条件，但**轮子还压在沿线上/悬空**，紧接着的 180° 旋转把它甩出去。

## 2. USER定的方案：安全里程计

记录"安全前进里程" M：小车在 NORMAL 状态每前进一拍，M 累加。触发边缘时，**后退时长 = clamp(M, MIN, MAX)**，后退期间不再看传感器（传感器语义在浅角下不可信）。因为 M 是实际开过的已知安全地面，盲退不超过它就必然还在台面上。

关键性质：

- NORMAL 永远是直线（+140,+140），M 就是当前直线段的长度 → 后退沿原轨迹 retracing，不会歪；
- 掉头完成后进入 NORMAL 时 M 清零重新累计（掉头后"身后"是桌沿方向，之前的里程作废）；
- 打滑使实际后退距离 < 名义值 → 天然保守方向；
- 已知限制：上电摆放时若离沿很近（M≈0），只有 MIN 兜底——**开机摆放要留余量**。

参考换算：140 档 = 140 脉冲/100ms ≈ 0.5 轮/s ≈ **7.1 cm/s**（2800 脉冲/圈 × 周长 0.1425m）。

## 3. 改动点（唯一文件 `Tabletop_Cliff_Avoidance.c`，Hi3861 侧，STM32 不动）

权威源码在本地 `backups/harmony_app/F.0_Tabletop_Cliff_Avoidance/Tabletop_Cliff_Avoidance.c`（改完 scp 覆盖 VM 同名文件，VM 路径 `/home/harmony/harmony/code/code-1.0/applications/sample/wifi-iot/app/F.0_Tabletop_Cliff_Avoidance/`）。

### 3.1 宏替换（现 66-70 行附近）

删掉四个 MIN/MAX（`EDGE_SINGLE_REVERSE_MIN/MAX_TICKS`、`EDGE_BOTH_REVERSE_MIN/MAX_TICKS`），换成：

```c
#define EDGE_REVERSE_MIN_TICKS            50U  /* 500 ms fallback when no safe mileage (boot near edge) */
#define EDGE_REVERSE_MAX_TICKS            200U /* 2.0 s cap ~= 14 cm of known-safe ground */
```

### 3.2 PhaseFController 增加两个字段（现 133-142 行）

```c
uint32_t safe_forward_ticks;  /* 10 ms beats of forward driving since arm/last recovery */
uint32_t reverse_ticks;       /* computed at edge entry: clamp(safe_forward_ticks, MIN, MAX) */
```

同步改 `phase_f_control_thread` 里的初始化列表（现 821-824 行，加两个 0U）。

### 3.3 M 的累计（控制主循环，现 848-881 行）

每拍循环末尾（`phase_f_send_command` 之后）：当 `controller.armed && controller.active && controller.state == PHASE_F_NORMAL` 时 `controller.safe_forward_ticks++`，封顶 `EDGE_REVERSE_MAX_TICKS`。（NORMAL 的命令恒为 +140/+140，不用判断方向。）

### 3.4 M → 后退时长的换算点（phase_f_update_controller，NORMAL case，现 653-658 行）

进入 EDGE 的瞬间：

```c
controller->reverse_ticks = controller->safe_forward_ticks;
if (controller->reverse_ticks < EDGE_REVERSE_MIN_TICKS) controller->reverse_ticks = EDGE_REVERSE_MIN_TICKS;
if (controller->reverse_ticks > EDGE_REVERSE_MAX_TICKS) controller->reverse_ticks = EDGE_REVERSE_MAX_TICKS;
controller->safe_forward_ticks = 0U;
```

注意 EDGE 状态之间会互切（单边↔双边，现 663-683 行），**互切不重新计算 reverse_ticks**（沿用首次进入时的值）；但传感器陈旧失效路径（现 868-870 行，active/armed 清零处）要一并 `controller.safe_forward_ticks = 0U`。

### 3.5 后退终止逻辑改为纯定时（phase_f_update_controller EDGE case，现 684-690 行）

改为：`elapsed >= EDGE_BRAKE_TICKS + controller->reverse_ticks` 就 `phase_f_prepare_recover()`，**删除传感器提前终止条件**。（EDGE_BOTH 单边先恢复→换边避让的分支 663-677 保留不动。）

> **实施备注（8-29 代码落地时修正）**：663-677 分支里"双边都恢复→满 reverse_min 提前退出"（668-672）本身就是传感器提前终止，且引用了 §3.7 要删的 `phase_f_reverse_min_ticks`，不能原样保留。实际实现 = **单边恢复→换边避让保留；双边恢复不再提前退出，统一交给纯定时器**（条件改成"恰好一侧仍危险才换边"，双边安全时落入底部纯定时终止）。语义与方案宗旨一致：后退期间不信传感器。

### 3.6 后退动作输出（phase_f_motion_command EDGE case，现 743-753 行）

`reverse_max` 局部变量换成 `controller->reverse_ticks`：刹车 100ms 后、剩余时间里发 `(-REVERSE_SPEED, -REVERSE_SPEED)`。

### 3.7 函数清理

`phase_f_reverse_min_ticks`/`phase_f_reverse_max_ticks`（588-598 行）删除或改为直接返回新宏（引用点全部换成 `controller->reverse_ticks` 后连函数一起删）。

### 不要动

转向段 300 ticks、去抖 1/2 拍、120ms 新鲜度、FAULT_STOP 3 轮锁存、协议层、STM32 侧，全部保持。
