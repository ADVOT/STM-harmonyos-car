# 任务12 SHT20温湿度传感器采集（信号量/I2C）流程梳理

> 阶段二第二个任务（8-28 第二次导出发布）。官方全文：`docx/实验计划_8.28更新.md` 3118-3373 行。
> 知识点：信号量 API（osSemaphoreNew/Acquire/Release/Delete）+ SHT20 I2C 采集。

## 状态

- 主线：**✅ 实机验证通过（8-28）**——每 3 秒一组：Thread1 释放 → Thread2 打印温湿度 + Thread3 打印，信号量节奏与同步全部符合预期；温度 32.3°C 缓降、湿度 38-39%（空调房），手捂/扇风可验证实时跟随
- 已知现象（非问题）：① 串口中文乱码 = printf UTF-8 vs UartAssist GBK 解码，数据正常，不管；② 板载 SHT20 读数高于室温 = PCB 上主控/稳压等芯片发热烘板，测的是板温不是气温；③ 吹气验证（8-28 实测）：湿度立刻明显变化（水汽直达），温度几乎不动（PCB 热容大，一口气带不走热量）——温度要看变化需手捂几十秒或持续扇风

## 硬件接线（与任务11 完全相同，不动线）

- SHT20 挂 **I2C0：GPIO9=SCL、GPIO10=SDA**（`hal_bsp_sht20.c:100-106`），从机地址 **0x80**（7 位 0x40），400kbps
- **与 OLED（SSD1306，地址 0x78）同一条 I2C 总线同一对引脚**，地址不同不冲突，两模块可同时挂
- 烧录/串口注意同前：串口开关打到 3861 端；Type-C 供电烧录时关闭小车电池开关

## 程序结构（按参考答案，已含修正）

- `sem1 = osSemaphoreNew(4, 0, NULL)`：最大值 4、初始 0
- thread1：每 3 秒 `osSemaphoreRelease` **两次** → thread2/thread3 各 Acquire 一次、同步执行；只放一次则 2/3 交替轮着跑
- thread2：`SHT20_Init()` 后循环 Acquire → `SHT20_ReadData(&temp,&humi)` → 打印
- thread3：循环 Acquire → 只打印
- `APP_FEATURE_INIT(i2c_sht20_demo)` 收尾

## 参考答案的坑（读文档预判，开工即修）

1. **信号量创建顺序竞态**：`i2c_sht20_demo` 先 `osThreadNew` 三个线程、**最后才** `osSemaphoreNew`——thread2/3 一启动就 `osSemaphoreAcquire(sem1)`，sem1 可能还是 NULL。与任务7"锁建在线程后"同款毛病，**建信号量必须挪到建线程之前**。
2. 文档里 `osSemaphoreRelease` 的函数定义贴错了（复制成 Acquire 的原型），仅文档瑕疵。
3. `hal_bsp_sht20.h` 里 `SHT20_I2C_SPEED 100000` 宏定义了但没用，实际 `SHT20_Init` 写死 400k。
4. 驱动每次 `SHT20_ReadData` 温/湿各发一次 NoHoldMaster 命令 + `usleep`（温度 85ms、湿度 50ms）再读 3 字节，未校验 CRC（第 3 字节）——官方驱动如此，采信前两字节即可。

## 预期现象

串口每 3 秒一组：`Thread1释放信号量!` → `temperature = xx.xx humidity = xx.xx` + `Thread2 得到信号量!` + `Thread3 得到信号量!`（2/3 顺序不定，属正常）。
