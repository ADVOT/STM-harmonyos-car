## 目标

双轮**速度闭环**（内环）：给定目标速度 → 编码器实测反馈 → PID 算修正 → `Set_Pwm` 写回，让两轮转速一致 → 车自然直行。官方作业：调目标值 `TageA/TageB` 观察车速变化。
（"一直走直线"的完全体 = 内环调速 + 外环里程差纠偏，见学习记录 8-26 第12条；本任务先做内环，外环后续叠加。）

## 参考答案的三个坑（8-27 分析，勿照抄）

1. **积分项是死代码**：`Integral_A` 累加+限幅了，但输出 `Pwm_A += ...` 里没加它——名义"增量式PI"，实际积分没接入。
2. **KP/KD 角色与标准公式对调**：代码 `pwm += KP·e(k) + KD·(e(k)−e(k−1))`。增量结构下 KP 乘误差本身、累加 = **积分作用**；KD 乘误差增量、累积 ≈ **比例作用**。调参时记住：官方的 KP 实际管"消静差"，KD 实际管"响应快慢"。
3. **`TageB = Rs_To_CPR(-1.0)` 不能照抄**：那是别人车右编码器相序反的情况。本车实测两轮同向为正（任务22/作业实测），**两边目标都用 +280**，否则原地打转。

## 代码结构（在 `motor_pwm/` 上加，不新建工程）

`USER/main.c`（任务22 作业版基础上）：

```c
/* 增量式 PID 状态（每轮一份）。结构体化：官方双函数 A/B 重复代码合一 */
typedef struct {
    float kp, kd;      /* 角色对调警告：kp 实为积分作用，kd 实为比例作用 */
    int   pwm;         /* 累计输出（增量式必须记忆） */
    float err_prev;    /* 上一次误差 */
} PID_Inc_t;

int Incremental_PID(PID_Inc_t *p, int encoder, int target)
{
    float err = (float)(target - encoder);
    p->pwm += (int)(p->kp * err + p->kd * (err - p->err_prev));
    if (p->pwm > 7199) p->pwm = 7199;          /* 输出限幅：PWM 满量程 */
    else if (p->pwm < -7199) p->pwm = -7199;
    p->err_prev = err;
    return p->pwm;
}
```

- 全局：`PID_Inc_t pidL = {7.0f, 0.003f, 0, 0}, pidR = {7.0f, 0.003f, 0, 0};`（官方初值起步，后调）
- `System_Control()` 改闭环：
  ```c
  L_speed = Read_Encoder(2);
  R_speed = Read_Encoder(3);
  Motor_L = Incremental_PID(&pidL, L_speed, TARGET_PULSES);  // 280
  Motor_R = Incremental_PID(&pidR, R_speed, TARGET_PULSES);
  Set_Pwm(Motor_L, Motor_R);
  printf("L %d/%d pwm %d | R %d/%d pwm %d\r\n", ...);  // 实测/目标/pwm，观察收敛
  ```
- `main()` 主循环清空（只留初始化和 `printf("ALL-ready")`），闭环全在 SysTick 100ms 节拍里——**不再需要 while 里 Set_Pwm/delay** 那套（任务22 测 P 的 MEASURE_MODE 开关可整段删掉，任务22 作业已成历史）。
- 任务22 作业版 main.c 留底：`backups/motor_pwm_main_task22_orig.c`（测P前原版）；作业版（双模式）改 PID 前再备份一份到 `backups/`。

## 外环：航向纠偏（8-27 USER提出"不能走斜线"，已落地代码）

- `YAW_CORRECT=1`（默认开）：`diff = Odo_L − Odo_R`（里程差=朝向的表）→ `corr = KP_YAW×diff`（初值 0.1，限幅 ±40）→ 差动叠加 `左目标=基准−corr / 右目标=基准+corr`
- 外环必须比内环慢（KP_YAW 小），画龙就减半、纠不动就加倍；稳定界 0<KP_YAW<1
- **局限（要写进报告）**：无陀螺仪，只能保持起步那一刻的朝向（相对航向）；起步摆斜 = 保持斜角走直线。绝对航向等超声波贴墙/视觉

## 任务模式：前进1米→倒退1米回起点（8-27 USER定，当前 main.c 形态）

- 行程状态机在 System_Control：`FWD`（+280 巡航，平均里程 ≥19649 换向并清双轮 PID 累加器）→ `BWD`（-280，平均里程 ≤0 停车）→ `DONE`（`Set_Pwm(0,0)`，持续打印终点 odo/diff）
- 1米 = 2800/0.1425 ≈ **19649 脉冲**；判距用两轮平均里程 `odo_avg=(Odo_L+Odo_R)/2`（=车心位置）
- 外环全程开：倒车时 corr 各量反号公式自动适配；前进段攒下的 diff 在倒退段被压回 0 → 终点 **位置(odo≈0)+朝向(diff≈0) 双回归**，这就是外环价值的演示
- 三档作业版已从 main.c 删除（留底 `backups/motor_pwm_main_task23_gearhomework.c`）；纯纠偏版留底 `backups/motor_pwm_main_task23_yaw.c`
- 验证看点：架空手拨单轮看 corr 反纠；实跑终点看串口 `[S] stop | odo X diff Y` 回零程度（打滑会让脉冲≠尺量距离，看串口别用尺量）；换向第一拍误差突变是硬刹车，0.14m/s 下无碍
- printf 列：`[F/B] L 实测/目标 pwm | R 实测/目标 pwm | odo diff corr`，目标列带符号（%+d）区分行程方向
- **架空 ✅（8-27）**：状态机走通，换向过冲 255 脉冲（≈1.3cm，100ms 检测粒度+惯性，正常）；FWD 段 diff±30 慢摆/corr±3（外环与内环滞后互磨的温和猎振，≈1.5mm 级无害，落地画龙再把 KP_YAW 减半）；BWD 段极干净 diff±7；**终点 odo 3 / diff 3 ≈ 0.15mm 双回归**（架空无打滑的理论上限）

- **队友代码对比（8-27，`backups/teammate_user/`）**：硬件层与我们完全一致；控制层=同款内环 KP=7.0/KD=0.003+死积分原样，**无外环无里程计**，5s 时间片换向，直线成功 → 内环零静差已天然补偿机械不对称（地面同速 L2650/R3400 的 pwm 差就是补偿在起效）；我们的外环在地面滞后下疑似振荡源（猎振可能发散成画龙）。**A/B 实验中途真相大白（8-27）：偏右的病根是地板本身斜**——车往低处偏载/侧滑，右轮承压大才多吃 30% pwm；编码器只认轮子转没转，侧滑它看不见，内外环其实都在按测量正常干活（日志里 diff 始终有界、corr 纠偏方向全对，就是证明）。机械检查/降 KP_YAW 全部不用做，已恢复 `YAW_CORRECT=1`（软启动保留），待平地复跑。教训：地面坡度这种环境干扰在传感器模型之外，调参前先换场地复现

## 调参路径（经验法，官方初值起步）

- 官方初值 `KP=7.0, KD=0.003`（角色对调后：7.0 是积分强度、0.003 是比例强度）
- 静差大（实测稳在 260 上不去 280）→ 加大 KP（积分作用）
- 震荡（实测围绕 280 来回甩）→ KP 太大或 KD 太小
- 响应慢（启动后很久才到 280）→ 加大 KD（比例作用）
- **左右电机阻力不同**（官方提醒）：两轮分别调，让两轮几乎同时到目标
- 失控保护：车跑飞/异常抖动 → 直接关电池

- 作业：目标改 140（0.5 转/s）/420（1.5 转/s），车速明显变档
