## 坑1：HiBurn 反复 `load fail 0xC35A69A5` —— 必须勾 Auto burn

- **症状**：Connect → `Ready to load at 0x10A000` → 涨 ~10 个 C → `load fail 0xC35A69A5`，无限重试；错误码每次只差 1；921600 和 115200 死法完全相同（定点击杀，非信号质量）。
- **根因**：**没勾 "Auto burn"**。勾上后一把过：loader → erase → download，各阶段 `Execution Successful` + `======`。
- 排除过程（都是弯路但值得记录）：降波特率（无效）、查 CH340 驱动（3.5.2019.1 经典稳定版，没问题）、查 VMware 抢串口（COM4 在 Windows 侧正常）、查 bin 完整性（strings 验证编译内容正确）。
- 结论：遇到 HiBurn load fail，**先检查 Auto burn 勾没勾**，别先怀疑线。

## 编译侧备忘

- 全量编译数分钟属正常（每次删 `out/wifiiot/` 重建）；成功标志 `ohos wifiiot build success!`。

- 远程非交互 ssh 直跑编译（`ssh harmony-vm 'python build.py wifiiot'`）会连环报错 `No option 'riscv32-unknown-elf-gcc_path'` → `Can't find gn`，最后还打印一大段 usage 带偏方向（真错误在输出第一行）。根因：工具链 PATH 写在 `~/.bashrc`（gcc_riscv32/ninja/gn/hc-gen/llvm 五行），**只有交互 shell 才加载**，非交互 ssh 不带；VSCode Remote 终端是交互 shell 所以一直没暴露。远程直跑写法：
  `ssh harmony-vm 'export PATH=~/gcc_riscv32/bin:~/ninja:~/gn:~/hc-gen:~/llvm/bin:$PATH; cd /home/harmony/harmony/code/code-1.0 && python build.py wifiiot'`
